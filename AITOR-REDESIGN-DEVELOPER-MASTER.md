# AITOR-REDESIGN-DEVELOPER-MASTER.md

## 0. OBJETIVO DEL ENCARGO

Aplicar la nueva Dirección Visual Digital de Aitor Soluciones sobre la web actual **sin reconstruir innecesariamente la infraestructura técnica ni perjudicar SEO, rendimiento, accesibilidad o conversión**.

Este documento es la **especificación maestra para desarrollo**. Sustituye cualquier instrucción visual anterior cuando exista contradicción.

No escribir ni publicar cambios estratégicos por iniciativa propia. Si algo no está definido aquí, conservar el comportamiento actual o elevar la decisión antes de modificarlo.

---

# 1. PRINCIPIO CENTRAL

La web debe dejar de parecer una plantilla compartida con otras marcas del grupo.

La nueva gramática visual de Aitor Soluciones debe sentirse:

**física + local + directa + humana + basada en resultados reales**

La secuencia conceptual de toda la experiencia será:

**VES EL PROBLEMA**  
↓  
**VES EL TRABAJO**  
↓  
**VES EL RESULTADO**  
↓  
**ENVÍAS FOTOS Y UBICACIÓN**

El diseño debe demostrar capacidad antes de declararla.

1. recibe un problema;

# 6. HERO — DIRECCIÓN CERRADA

## ELIMINAR

No utilizar como composición dominante:

**texto izquierda / visual derecha**

No usar reparto 50/50.

No usar:

- mockup;
- ilustración tecnológica;
- render 3D;
- bento;
- tarjetas flotantes;
- vídeo autoplay;
- gráficos abstractos;
- imagen generada por IA.

## NUEVA COMPOSICIÓN

### HERO FOTOGRÁFICO DOCUMENTAL

Una fotografía real debe dominar la primera pantalla.

La composición puede usar:

- mensaje parcialmente superpuesto;
- bloque compacto integrado;
- franja inferior;
- título encima de la fotografía;
- texto en zona segura de la imagen.

Debe comunicar en menos de cinco segundos:

1. Jardinería es el servicio principal.
2. También existe mantenimiento de propiedades.
3. Se trabaja en Alcanar y alrededores.
4. Se puede contactar inmediatamente.

## CONTENIDO ORIENTATIVO

### H1
**Jardinería y mantenimiento de propiedades en Alcanar y alrededores**

### Apoyo
Mantenimiento de jardines, desbroce, poda y puesta a punto de exteriores. También cuidamos viviendas y segundas residencias.

## CTA PRINCIPAL
# **Enviar fotos y ubicación**

No usar “Pedir presupuesto” como CTA global principal.

## CTA SECUNDARIOS
- Pedir presupuesto.
- Llamar.
- Ver trabajos.

# 11. GRID

## PRINCIPIO

**Asimetría práctica.**

Puede mantenerse una base técnica de 12 columnas, pero no mostrar siempre composiciones simétricas.

Usar:

- 8 / 4;
- 7 / 5;
- 5 / 7;
- imagen completa + bloque estrecho;
- lista vertical + fotografía;
- fotografía a sangre;
- contenido compacto.

Evitar:

- 3 cards idénticas por fila;
- 4 cards equivalentes;
- 6/6 repetido en cada sección;
- bento grids como lenguaje general.

# 12. TIPOGRAFÍA

## DISPLAY / TITULARES

Utilizar una sans robusta, humana y diferenciada.

Dirección recomendada:

**Barlow Semi Condensed** o equivalente.

Debe transmitir:

- oficio;
- claridad;
- contundencia;
- cercanía.

## CUERPO / UI

Usar una fuente altamente legible.

Opciones:

- Source Sans 3;
- Inter, únicamente como UI/cuerpo si no domina la personalidad.

## REGLAS

- H1 potente, 1–3 líneas.
- H2 mayoritariamente alineados a la izquierda.
- Párrafos cortos.
- Mayúsculas pequeñas únicamente para etiquetas funcionales.

## EVITAR

- Inter como voz única de toda la web;
- Poppins/Montserrat como solución genérica si recrean sensación de plantilla;
- tipografía futurista;
- serif dominante;
- tracking exagerado.

# 13. COLOR

Mantener identidad:

- azul marino;
- naranja;
- blanco;
- grises neutros.

Referencias actuales:

- Azul: `#071E3B`
- Naranja: `#F36A10`

Si existe manual oficial posterior, prevalece el manual.

## USO

### Fondo dominante
Predominantemente claro.

Aproximación visual:

- 65–75 % blanco/gris muy claro;
- 20–30 % azul marino;
- menos del 10 % naranja.

### Azul
Estructura, texto, confianza, footer, secciones de contraste.

### Naranja
Acción, indicadores, líneas, estados, detalles, comparación.

## NO USAR

- glow;
- neón;
- mesh gradients;
- fondo oscuro tecnológico continuo;
- grandes áreas naranjas;
- naranja para texto pequeño sin contraste suficiente.

# 15. ANTES / DESPUÉS

Debe convertirse en una firma visual de marca.

## DESKTOP

Preferencia:

- side-by-side;
- imágenes con mismo peso;
- mismo ratio;
- etiqueta `ANTES`;
- etiqueta `DESPUÉS`;
- localidad;
- trabajo realizado.

Cuando las fotos estén alineadas, se permite comparador deslizante.

## MOBILE

- apilado;
- o slider con alternativa accesible.

## REGLAS

- no depender exclusivamente del drag;
- no manipular el resultado;
- no usar filtros distintos;
- no ocultar el “antes”.

Puede utilizarse una barra/corte diagonal naranja como recurso de unión visual.

# 16. TARJETAS

- agrupa una unidad independiente;

- rectangular;
- radio moderado;
- sombra mínima o inexistente;
- más contenido real;
- menos decoración.

No usar el mismo componente para:

- servicios;
- beneficios;
- testimonios;
- proceso;
- localidades;
- confianza.

# 21. MOTION

## PRINCIPIO

El movimiento representa cambios o resultados físicos.

## PERMITIDO

- comparador;
- revelado de imágenes;
- transición de trabajo;
- estados;
- galería;
- FAQ;
- menú;
- pequeñas entradas.

## RITMO

Microinteracciones:

- 160–240 ms aprox.

Entradas:

- 250–400 ms aprox.

## PROHIBIDO

- cards flotando;
- parallax gratuito;
- scroll-jacking;
- partículas;
- flechas animadas continuamente;
- texto palabra a palabra;
- counters;
- cursores personalizados;
- vídeo de fondo;
- movimiento SaaS.

Respetar `prefers-reduced-motion`.

# 40. RENDIMIENTO

Las imágenes grandes no deben perjudicar Core Web Vitals.

Aplicar:

- AVIF/WebP cuando corresponda;
- `srcset`;
- `sizes`;
- lazy loading;
- preload solo cuando sea necesario;
- dimensiones declaradas;
- compresión;
- hero prioritario;
- fuentes optimizadas;
- JS limitado.

Evitar:

- dependencias visuales pesadas;
- librerías de motion innecesarias;
- múltiples sliders;
- vídeo pesado.

- slugs;
- metadata;
- schema;
- enlaces internos;
- sitemap;
- canonical;
- hreflang;
- páginas locales;
